Deck Host

desk CO.HOST-DECK windows for ROMs

why

Deck Host is the window runtime for ROMs. The ROM is the product. The host is the chrome that makes it feel like a program instead of a tab.

It was made so a pocket tool could be double-clicked, sit in its own window, and ship as one install — not open a browser, keep a server console running, and remember the port. One folder, one icon, the ROM’s UI, quit that actually quits. Development may still split server and window. Delivery is not supposed to.

where it came from

The shell is a rework of the old myPI pocket-browser. Pocket internet needed a real window. Deck Host generalizes that: any ROM can wear it, not only myPI. ROM Cat files it as CO.HOST-DECK. The primary face is ROM Launcher (CO.HOST-001-LAUNCH).

three rooms

  • Shell — the window: caption, drag, deep mode, spawn and health, profiles (desk, rail, office).
  • ROM Launcher — a start menu of cartridge cases. Identity from ROM Cat. Recipes only know how to run.
  • Receiver — a felt stage that is a ROM, not a second launcher.

A typical glass ROM starts a local server, waits until it is healthy, then opens frameless glass on that URL. Static toys can skip the server so a frozen exe is enough. The later dream is a ROM deck — many carts, one host. Today the house mostly does one ROM, one window, with the launcher as the shelf.

the title bar

The host does not own a ROM’s data, verbs, or world. Caption integration is how a ROM becomes the title bar: data-deck-chrome, data-deck-drag — Pocket Go’s Win 3.1 chrome, the desks’ rails, the launcher’s top strip. That is the point of a real window on this stack.

Deck Host exists so the tools can live as cartridges in glass, not pages in a browser. The launcher is how you pick a cart. The shell is the deck they plug into.
